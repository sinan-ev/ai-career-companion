
## 🛠️ Step-by-Step Execution Flow

### 1. Document Chunk Generation
The RAG pipeline extracts semantic metadata rather than indexing the entire raw CSV (which would overflow LLM token limits). In `context_builder.py` ([L48-L62](file:///d:/weekly%20Task/badge%204/Project/Code/Backend/module3/services/context_builder.py#L48-L62)), facts are chunked into:
* General dataset profile description.
* Descriptions of column definitions mapping semantic meanings (e.g. `"Column 'sales': The total revenue generated by store location"`).

### 2. Embedding & Vector Storing
Once chunks are compiled, `rag_engine.py` calls `store.add_texts(chunks)`:
* **The Vector Store** is an in-memory repository storing raw text chunks in the `self.documents` list and their vector representations in `self.embeddings`.
* **The Embedder** is currently configured as a **mock/dummy implementation**, generating random 128-dimensional float arrays via `np.random.rand(128).tolist()`.

### 3. Similarity Search & Retrieval
During a chat query, `retriever.retrieve(query)` runs a search against the vector store:
* **Current Mock Search**: To prevent validation engine rejection (which requires a retrieval similarity score of at least `0.7`), the `similarity_search` method is hardcoded to return the top `k` chunks paired with a fixed similarity score of `0.85`:
  ```python
  docs = self.documents[:k]
  scores = [0.85] * len(docs)
  return list(zip(docs, scores))
  ```
* **Retrieval Compilation**: The retriever aggregates the matched text chunks by joining them with newline characters (`\n`) and wraps the payload inside a `RetrievalResult` dataclass container.

## ⚠️ Notes for Production Upgrades

> [!NOTE]
> The current RAG implementation uses **mock vectors and mock search similarity scores**. 
> While this works for local testing and matches your current validation pipelines, transitioning to a production-grade system will require:
> 1. Replacing `Embedder` with a real embedding client (e.g. `HuggingFaceEmbeddings`, `SentenceTransformers`, or the GCP Vertex AI / OpenAI Embeddings API).
> 2. Updating `similarity_search` in `VectorStore` to calculate actual **cosine similarity** or Euclidean distance between query vectors and stored chunk vectors.
